# Plan 0017: 1D simulations (roadmap phase 5)

_Done._ What changed on the way: Java's 1D wells forget to convert the depth from kJ/mol, so the port fixes that and there is no `1Dwells` fixture; the hole is refused in 1D rather than treated as solid; a dimension whose particles don't fit is refused with a notice and the run carries on; and two 1D presets (`1Dequalmass`, `1Dheavy`) make 1D reachable from the menus, since Java shipped none.

Issue: joshuata/boltzmann4d#69. Roadmap: `.agents/plans/0006-spec-roadmap.md`, Phase 5.

Requirements: SIM-7, SIM-8; PRED-1, PRED-3 (1D columns), PRED-10; PRES-3 (pN). Unlocks STORY-23 and the 1D row of STORY-4.

## Steps

1. **Parity fixtures.** `ParityDump` already writes any dimension (Java's `Particle1D` reports `y = 0`). Add 1D scenarios to the fork's `tests/edu/byu/chem/boltzmann/tools/scenarios/` and list them in `build.xml`'s `parity-dump` target: a single mass in a box (`1Dequal`), a mixture (`1Dmixture`), periodic (`1Dperiodic`), a divided arena (`1Ddivided`), and a conducting divider (`1Ddivided-conducting`). Regenerate with `mise run java:parity`.
2. **Engine.** `packages/engine/src/sim/particle-1d.ts` ports `Particle1D`: prediction (pair, wells, periodic image, walls, divider), collisions and boundary events, with the same function shapes as `particle-2d.ts` so `Simulation`'s `MOTION` table takes a `1` entry. `y`/`vy` stay 0. The cell grid gets a 1D mode (one row). Unsupported in 1D, rejected by `Simulation` and hidden in the UI: the piston (Java has one; left for a follow-up), the hole (SIM-15: 2D and 3D only; Java treats it as a solid divider), drawn walls and the attractive wall. `parity.test.ts` stops skipping 1D.
3. **Collisions along the line of centres.** Java's 1D collision uses the raw velocities, which is the same as projecting onto the line between the centres for elastic and well collisions (negating both inputs negates the result exactly), but its reaction branch assumes `this` is the left particle, so a reacting pair whose first particle is on the right passes through each other. Project as in 2D: elastic and well results stay bit-identical to Java, and reactions keep the particles' order. Record this in `docs/physics-differences.md` and on #24.
4. **Statistics and pressure.** Bug 4 (`avgRelativeVelocity` in 1D) is already fixed in `formulas.ts` (plan 0004); note it on #24. PRED-3: 1D collision rates use `L_net = L − Σ 2rᵢ` (`netLength`). PRES-3/PRED-10: the pressure readout reads pN (force), the wall "area" is 1, and the Real prediction in 1D is the exact hard-rod equation of state `N k T / L_net` (the hard-disk Padé factor is 2D/3D only). The virial method's volume is the length.
5. **Renderer.** `view-2d.ts` draws 1D: the particles on a horizontal line through the middle of a thin arena strip, walls and divider as in 2D, periodic ghosts in x only.
6. **Dimension control.** A 1D / 2D / 3D toggle in the Arena panel. Changing it restarts: `withDimension` (engine `scenario/edit.ts`) changes `arena.dimensions`, re-places every particle at random at its kind's temperature, and drops what the new dimension can't have (hole → divided box, piston → box, drawn walls and spawn regions). The statistics panel offers only the plots that exist in the dimension (no y/z velocity in 1D).
7. **Docs.** Spec Web port notes (SIM-7, SIM-8, PRED-3, PRED-10, PRES-3, STORY-23), the roadmap's Phase 5 status, the user docs, `docs/physics-differences.md`; archive this plan.
